# Студия «Без сказок»

Пульт конвейера: выпуски, журнал запусков с выгрузкой в JSON, расходы на Claude с предупреждением о балансе, источники новостей.
Плюс MCP-вход, через который Claude сам читает журнал и помогает чинить.

## Источники

Список источников живёт в Студии (таблица `studio_sources`), а не в Google Таблице.

- Добавить: вставить ссылку на сайт, `t.me/канал` или `youtube.com/@канал` → «Проверить» → «Сохранить и включить».
  Или «Добавить списком»: много ссылок сразу, строка `# Группа` задаёт группу; есть стартовый набор (`app/catalog.py`).
- Группы (роль источника для сценариста): первоисточники, украинские СМИ, фронт, Россия изнутри, мир и США, мнения,
  «только сигнал» (никогда не подаётся как факт). Включать и выключать можно по одному, группой или все сразу;
  группу можно сменить прямо в строке источника, фильтр показывает только включённые или только выключенные.
- Группу Студия ставит сама (`app/catalog.py`): узнаёт известные каналы и сайты, госсайты относит к первоисточникам,
  российские и белорусские сайты — к «только сигнал», украинские сайты — к украинским СМИ, YouTube — к мнениям.
  Незнакомый Telegram-канал остаётся без группы. Кнопка «Разложить по группам» делает это для уже добавленных.
- Стартовый набор сервер проверяет сам после каждого обновления и раз в сутки: что открывается с нашего адреса.
  Итог виден в «Добавить списком» и в `list_sources` для Claude.
- Reuters, AP и Bloomberg своих открытых лент не дают: их заголовки о войне и России берутся через поиск Google Новостей.
- Вверху — направления («папки», сейчас одно — «Новости»), под ними вкладки групп и фильтр «включённые / выключенные».

## Расшифровки YouTube (Apify)

Наш сервер YouTube за субтитрами не пускает, поэтому расшифровки идут через Apify (`app/apify.py`, сервис
`karamelo/youtube-transcripts`, около $5 за 1000 видео; бесплатно Apify даёт $5 в месяц).

- Ключ вводит владелец: Настройки → Ключи сервисов → Apify. Перед сохранением Студия проверяет ключ у Apify.
  Хранится зашифрованным (`app/vault.py`, шифр из `STUDIO_SECRET`), наружу не отдаётся: ни в API, ни в MCP, ни в журнал.
- Берутся только новые видео включённых источников, без шортсов, пачками до 15 штук, не больше N в сутки (по умолчанию 20).
  Когда за месяц на Apify потрачено больше лимита (по умолчанию $4), Студия ставит расшифровки на паузу.
- Сценарист (К3) из длинной расшифровки берёт куски, где говорят о теме сюжета, плюс начало видео.
- Выключенный источник не собирается, и его материалы не попадают в сценарий.
  Для сайта Студия сама находит RSS-ленту, Telegram читается через RSSHub, YouTube — через ленту канала.
- Студия сама собирает свежее (за 48 часов) раз в 30 минут и по кнопке «Собрать сейчас», складывает в `k_items` с `source_id`.
- У каждого источника видно состояние: работает, не открывается (с причиной), молчит больше 3 суток, выключен.
  Если источник не открывается ~3 часа или молчит трое суток — сообщение в Telegram (не чаще раза в сутки).
- Ходит только на обычные адреса в интернете: внутренние адреса сервера и локальная сеть запрещены.

## Что где

| Папка | Что внутри |
| --- | --- |
| `studio/` | Студия: FastAPI (`app/`) и веб-интерфейс без сборки (`web/`) |
| `worker/` | сервер монтажа (FFmpeg + Playwright) — тот же, что работает на сервере |
| `deploy/` | установщик (один раз), автообновление, настройки docker compose |

## Как обновляется

1. Claude отправляет изменения в ветку `main`.
2. На сервере таймер `studio-update.timer` раз в 2 минуты забирает новую версию с GitHub (только чтение).
3. Изменилась папка `studio/` — Студия пересобирается. Изменилась `worker/` — сервер монтажа пересобирается, только когда свободен.
4. Студия обновляется осторожно. Пока она публикует в Facebook, Threads или Telegram из очереди, обновление ждёт. Новая версия не собралась — работает прежняя. Собралась, но 90 секунд не отвечает — сервер сам возвращает прежнюю версию, а эту больше не пробует, пока не придёт исправление.
5. Итог приходит в Telegram. Журнал обновлений: `/opt/n8n/studio-update.log`.

Секреты и личные данные в репозиторий не попадают: ключи, номера чатов и ссылки на таблицы лежат только на сервере (`/opt/n8n/studio.env`, `konveyer-worker/worker.env`).

## Внешний вид: аппаратная

Студия оформлена как настоящая аппаратная: тёплый графит и бетон, свет ламп накаливания. Цвет означает состояние: красный — эфир и ошибки, янтарь — твой ход (кнопки, запись), зелёный — готово.

- **Табло** вверху боковой панели горит по самому важному выпуску: «ЗАПИСЬ» — сценарий ждёт записи, «МОНТАЖ» — идёт сборка, «ПРОВЕРКА» — готов и ждёт решения, «В ЭФИРЕ» — публикуется. Нажатие открывает этот выпуск. Обновляется раз в минуту.
- **Студийные часы:** 60 огней секунд по кругу и цифры как на табло. Режим «Хронометр» — секундомер для записи: нажми на часы — пошёл, ещё раз — пауза; помнит себя после обновления страницы. На телефоне — маленькие часы и лампа в верхней строке.
- **«Сейчас в студии»** на Обзоре: монитор с выпуском (кадр, плановая длительность или время монтажа) и следующий шаг с кнопкой — «Открыть суфлёр», «Проверить и опубликовать».
- **«Что сделать сейчас»** на Обзоре — короткий список дел, как «входящие» у больших сервисов: записать выпуск (сценарий ждёт) → «Суфлёр»; проверить и опубликовать → «Открыть»; выпуск с ошибкой; разобрать ошибки конвейера; пополнить баланс Claude. Дел нет — так и написано.
- **Тема:** «Студия» (тёмная, по умолчанию), «День» и «Авто» — внизу боковой панели; запоминается в браузере (`web/theme.js`, ставится до отрисовки).

### Аппаратная 2 (28.11): конвейер на виду

Подсмотрено у лучших в своих нишах: доски по этапам и статусы — у трекеров студий (Kitsu, ShotGrid) и редакций (Superdesk: «столы» и «этапы»), очередь с окнами публикации — у Buffer, шаблоны — у Opus Clip, быстрый переход — у Linear.

- **Меню по группам:** «Работа» (Обзор, Выпуски, Суфлёр), «Настройка» (Направления, Источники, Подключения), «Служебное» (Журнал, Расходы, Настройки). Счётчики — где ждут тебя: янтарный у «Выпусков» (ждут проверки) и «Суфлёра» (ждут записи), красный у «Журнала» (ошибки не разобраны). Считает `GET /api/nav` раз в минуту (вместе с табло).
- **«Линия» на «Обзоре»** — конвейер по станциям: Сценарий → Монтаж → Проверка → Публикация → В эфире, у каждой число выпусков и лампа: янтарь — ждут тебя, мигает — работает машина, зелёный — вышло (за неделю). Станция ведёт на доску «По этапам». Под «Линией» — что выйдет по расписанию. Ниже рядом: «Что сделать сейчас» и «Сейчас в студии»; сервер — одной строкой лампочек, подробности по нажатию.
- **Карточки выпусков** — с кадром (обложка выпуска; у сценария — плановое время на табло), цветной меткой направления и одной янтарной кнопкой главного действия: «Записать», «Проверить» или «YouTube». Не загрузился кадр (файл уже убран) — заставка.
- **Шаги выпуска** вверху карточки: Сценарий → Запись → Монтаж → Проверка → Эфир — где он сейчас и когда прошёл каждый этап.
- **Быстрый переход:** Ctrl+K (или «/», или лупа вверху меню) — набери пару букв: раздел, действие («Новое направление», «Свой текст в суфлёр», «Пульт») или свежий выпуск, Enter.
- **Телефон:** внизу четыре вкладки (Обзор, Выпуски, Суфлёр, Журнал) и «Ещё» — лист с остальными разделами, темой и выходом. Отчёт JSON на телефоне — в «Журнале».
- **Часы** по умолчанию — одной строкой; «Больше» — круглые с огнями секунд (запоминается).
- **Подключения:** сверху сводка — четыре площадки лампами; «Кто сюда публикует и что вышло» — свёрнуто.
- **Шрифты** свои, с сервера Студии (`web/fonts`, лицензия OFL): Fira Sans — текст, Fira Sans Extra Condensed — заголовки и цифры, DSEG7 — часы. Внешних запросов нет — правила безопасности страницы (CSP) их и не пустят.

## Суфлёр

Вкладка «Суфлёр»: сценарии конвейера (из выпусков) и свои тексты, которые вставляешь сам.

- Текст идёт по экрану со скоростью «слов в минуту» (по умолчанию 130, как в настройках направления). Красные треугольники показывают строку, которую читаешь сейчас.
- Управление: пробел или касание — пуск и пауза (первый пуск — отсчёт 3-2-1, и с начала, и с выбранного сюжета); ↑ ↓ — скорость; ← → — разделы; 1–9 — к сюжету; колёсико или палец — подвинуть текст; Esc — пауза, на паузе — выйти.
- **Кликер для презентаций или педаль** (они нажимают клавиши): PageDown, F5, B или точка — пуск и пауза; PageUp — абзац назад (сбился — к началу абзаца, чтение не прерывается); Home — в начало.
- **Пульт с телефона**, как у Teleprompter и PromptSmart: суфлёр открыт у камеры (планшет, ноутбук), а на телефоне — Студия → Суфлёр → «📱 Пульт» (`#/remote`): крупные кнопки «пуск/пауза», «сюжет назад/вперёд», «абзац назад», скорость, шрифт, зеркало, «в начало»; видно, что читается, раздел, сколько осталось и текущую строку. Нужен тот же вход в Студию на обоих устройствах. Устроено через Студию (`studio/app/remote.py`): суфлёр раз в 0,4 с сообщает состояние и забирает команды, пульт раз в 0,7 с смотрит состояние; всё в памяти, команда живёт 5 секунд — старое нажатие не сработает внезапно. В шапке суфлёра горит «📱 пульт», пока телефон на связи.
- **Сюжеты с хронометражем** на странице текста: каждый раздел — сколько слов, сколько идёт при твоём темпе и с какой минуты начинается, у каждого «▶ Читать отсюда» (заголовок сюжета в тексте — тоже). Как сюжеты в выпуске новостей у больших редакций.
- В сценарии видно, где будет вставка (◆) и где шортс (▶ … ■). На странице сценария — список шортсов и лист фактов со ссылками.
- Свой текст размечается так: `# Заголовок` — раздел, `//` — пауза (`///` — длинная), пустая строка — новый абзац.
- Настройки (размер, ширина строки, зеркало для стекла суфлёра, пауза перед разделом) запоминаются на устройстве. Экран не гаснет, пока суфлёр открыт.
- «Следить за голосом» (проба, Chrome): текст идёт за тем, что ты читаешь вслух, а не по таймеру. Нужен доступ к микрофону.
- Код: `studio/app/prompter.py` (тексты → блоки), плеер — `openPlayer` в `studio/web/app.js`. Свои тексты хранятся в таблице `studio_texts` и входят в копию базы.

## Выпуски: просмотр и решение

На странице «Выпуски» — направления сверху («Все направления», «Без сказок — новости», …, с числом выпусков) и два вида: «Списком» и «По этапам». «По этапам» — доска, как у досок задач: колонки «Сценарии» (ждут записи) → «Монтаж» → «Проверка» → «Публикация» → «Вышли» (+ «Ошибки», если есть); у карточки — что сделать дальше («Суфлёр», «Проверить», «YouTube»). Вид запоминается в браузере; заменённые, отменённые и записанные сценарии — только в виде «Списком». API: `GET /api/episodes?direction=…` и список направлений с числом выпусков (`directions`).

В карточке выпуска (Выпуски → «Подробнее») готовое видео играет прямо в Студии, рядом — шортсы, главы для описания и список «Проверь перед публикацией»: вставки, в месте которых монтаж не уверен (кнопка с временем перематывает видео к этому месту), и вставки, которые не встали.

- **Опубликовать / Пересобрать / Отменить** — те же действия, что кнопки бота под превью. Студия меняет статус выпуска в базе (с проверкой, что он не изменился), пишет в журнал действий и присылает в Telegram «Из Студии: …».
- Публикацию Студия только заказывает (статус `publish_requested`). Раз в минуту процесс n8n «Студия · 🎬 Публикация из Студии (очередь → К6)» забирает заявки и запускает К6 — тот же путь, что у кнопки бота. Без вебхука и лишних ключей: заявку может оставить только тот, кто вошёл в Студию.
- Пересборка, как и в боте, отмечает выпуск `redo` и забывает файл записи — монтаж (К5) соберёт его заново под новым номером в течение 2 минут.
- **Удалить** (корзина на карточке выпуска, в карточке «Подробнее», в списке суфлёра и на странице сценария): удаляет выпуск или сценарий целиком — запись в базе, вставки и папку выпуска на сервере (её удаляет сервер монтажа: Студия видит файлы только на чтение). Остаются расходы (деньги уже потрачены) и отметка «файл с Диска уже обработан», чтобы монтаж не собрал исходник заново; сам исходник на Google Диске не трогаем. Пока идёт монтаж или публикация, удалить нельзя.
- Код: `episode_action`, `delete_episode` и `_video` в `studio/app/services.py`, кнопки — `openEpisode` и `deleteEpisode` в `studio/web/app.js`.
- **Как прошёл выпуск** (там же): этапы со временем — сценарий, запись, монтаж, проверка, публикация — и сколько длились монтаж, твоя проверка и публикация, сколько шортсов готово, какая была подача. Время этапов база отмечает сама: триггер `studio_k_timeline` на `k_episodes` дописывает `meta.timeline` при каждой смене статуса, кто бы её ни менял (n8n или Студия). Учёт идёт с 28.11; у старых выпусков блока нет.
- Видео выпуска лежит на адресе сервера монтажа, а Студия — на своём поддомене, поэтому в политике безопасности Студии `media-src 'self' https:` (без этого браузер не играл бы видео в карточке).

### Монтажный стол: поправить вставки без пересъёмки

В карточке готового выпуска — блок «Монтажный стол» (свёрнут; сам открывается, только пока идёт пересборка). Там все вставки по времени: превью, номер, время, длительность, откуда.

- **Как найти плохую вставку:** поставь видео на паузу, когда она на экране, — под плеером появится «На экране вставка №… · Поправить». Ещё «Поправить» есть у каждой строки «Проверь перед публикацией». Нажатие на превью или время в столе перематывает видео к вставке.
- **Что можно:** убрать; на секунду раньше / позже; короче / длиннее (от 1 до 30 с); ведущий в углу поверх вставки или вставка на весь экран; заменить — скрином страницы по ссылке или своим файлом (PNG, JPG, WEBP, MP4, MOV, WEBM до 25 МБ); поправить подпись на кадре («Архивное фото», «Скриншот · …» — нажми на подпись в строке; у своего файла подписи нет, пока её не впишешь, у скрина — адрес сайта).
- **Исправить слово в субтитрах:** в шортсах субтитры вшиты в видео, ошибку в фамилии видно всем. «Как сейчас» → «Как надо» → «Найти»: Студия показывает, в каких шортсах и сколько раз слово стоит (без учёта регистра и «е/ё», только целые слова; номера и время субтитров не трогает), потом «Заменить» — в правки. Пустое «как надо» — убрать слово. Если поправлены только субтитры, сам выпуск не пересобирается, только шортсы (`only_shorts` в плане). В субтитрах выпуска (`subs.srt`) слово тоже меняется, но в YouTube их публикация не грузит — YouTube делает свои.
- Правки копятся; **«Пересобрать с правками»** — одна пересборка на все. Видео, шортсы, обложка и субтитры перезаписываются на месте, ссылки не меняются; итог приходит в Telegram, плеер в Студии сам берёт новый файл. **«Вернуть как было»** — пересобрать по первому, автоматическому плану.
- **Когда нельзя:** без исходника — после публикации его убирает К6, неопубликованный ночная уборка (К7, `raw_days: 7`) хранит 7 дней, потом стол только показывает; во время монтажа или пересборки; после того как выпуск отправлен на публикацию. Пересборку не пустит, если сервер монтажа занят другим выпуском. Править может только владелец кабинета.
- **Как устроено** (`studio/app/montage.py`): план монтажа К5 сохраняет в `k_episodes.edl`. Студия собирает новый план в `edl_next` и отдаёт серверу монтажа (`POST /render`, тот путь, что у К5); первый план хранится в `edl_auto`. Пока идёт пересборка — статус `rendering` и `meta.montage_job`; фоновый цикл спрашивает сервер раз в 15 секунд и возвращает выпуску прежний статус (перезапуск Студии пересборку не теряет). Новые картинки делает сервер монтажа (`/screenshot`, `/save`) — у Студии файлы только на чтение. Поправленные вставки помечаются в плане (`edited`) и уходят из «Проверь перед публикацией»; «Вернуть как было» возвращает исходный список (`meta.stats_auto`). Если сервер упал уже после замены видео (на шортсах или обложке), Студия так и пишет — «пересобрано не до конца», план остаётся новым, как у видео.
- Доработка «после сборки» (К8, колонка `enhance_after` в таблице направлений: резкость, цвет) при пересборке со стола не повторяется. Сейчас она нигде не включена; если включишь — после правок на столе её надо запустить заново.
- Сервер монтажа (`worker/app.py`): понимает `only_shorts` и пишет шортсы, как и сам выпуск, во временный файл с подменой целиком — упал на середине, прежний файл цел. Обновляется сам из GitHub, только если при установке совпадал с репозиторием; старая версия `only_shorts` не знает и пересобирает всё — итог тот же, только дольше.

### Публикация: тексты и кнопки по площадкам

В карточке выпуска — блок «Публикация»: тексты для каждой площадки и своя кнопка «Опубликовать» у каждой.

- **Тексты пишет Claude** (`studio/app/pubtexts.py`): сам, как только готов монтаж (раз в минуту ищет выпуски с готовым видео без текстов, до 2 попыток), или по кнопке «Написать тексты» / «Переписать» (всё или одну часть). Пишет из сценария и листа фактов (факт из одного источника — только со ссылкой на источник, неподтверждённое — не как факт); для своего видео без сценария — из субтитров. Если тексты уже написаны у сценария, запись по нему берёт их, а не пишет заново.
- **Что пишет:** YouTube — заголовок, описание, 2–3 хэштега по темам; каждый шортс — заголовок, описание, подпись для TikTok, хэштеги; Facebook — текст над видео; Threads — цепочка из 3–6 постов. Хранится в `k_episodes.meta.pub`, правится прямо на странице («Сохранить правки»), публикуется ровно сохранённое.
- **Хэштеги канала** — «Направления» → Публикация → «Хэштеги канала» (у новостей: `#БезСказок #новости #война #политика`); добавляются ко всем публикациям.
- **Claude через n8n:** Студия зовёт процесс «Студия · ✍️ Claude для Студии» (`POST /webhook/studio-claude`, ключ сервера монтажа). Ключ Anthropic остаётся в n8n; процесс сам ставит модель и потолок токенов; расход виден в «Расходах» у выпуска, как у остальных шагов.
- **Кнопки:** YouTube — заказывает К6 (выпуск и шортсы; доступ — как в направлении). Facebook и Threads — Студия публикует сразу, в фоне (`POST /api/episodes/{id}/publish/{facebook|threads}`, только владелец кабинета). Включённые в направлении Facebook/Threads, как и раньше, выходят ещё и сами следом за YouTube.
- **Threads цепочкой:** первый пост — со ссылкой на видео (YouTube, если он открыт, иначе Facebook), каждый следующий — ответом на предыдущий (`reply_to_id`). Для ответов Meta просит разрешение `threads_manage_replies`; без него выходит первый пост, а Студия пишет, что добавить. Повтор продолжает цепочку с места (`threads_chain`, `threads_total` в `meta`).
- **TikTok вручную:** у каждого шортса «Скачать» (`GET /api/episodes/{id}/file/{short}` — файл с сервера монтажа) и «Подпись для TikTok» (подпись + хэштеги в буфер обмена).
- **Telegram:** карточка «Telegram · пост в канал» — текст поста (до 800 знаков; Claude пишет его вместе с остальными, у старых выпусков сначала подставлен текст Facebook) и «Ссылка в посте»: сама (YouTube, если доступ открытый или по ссылке, иначе Facebook), YouTube, Facebook или без ссылки. Кнопка «Опубликовать в Telegram» — сразу, в ответе ссылка на пост. У каждого шортса — «В Telegram»: видео отдельным сообщением. Подробнее — «Подключения» → Telegram.

### Публикация по расписанию

Как очередь у Buffer: окна публикации задаются один раз в направлении («Направления» → Публикация → «Окна публикации», например `19:00` или `9:30, 19:00`, до 6 в день, по часам Студии). У готового выпуска рядом с «Опубликовать на YouTube» появляется «В окно: сегодня в 19:00» — дату выбирать не надо. «Другое время» — своё время (не раньше чем через 2 минуты и не дальше 60 дней).

- Время хранится в выпуске (`k_episodes.meta.publish_at`, UTC). Раз в 30 секунд Студия (`app/schedule.py`) смотрит, чьё время пришло, и делает ровно то же, что кнопка «Опубликовать на YouTube» (`publish_requested` → К6). Facebook, Threads и Telegram уходят следом сами, если так включено в направлении.
- Расписание снимается до публикации: второй раз сам не запустится. Если к этому времени выпуск уже опубликован — тихо; отменён или пересобирается — сообщение в Telegram.
- Видно: на карточке выпуска и на доске («сегодня в 19:00»), строкой под «Линией». Отменить — «Отменить расписание» на странице выпуска.
- API: `GET|POST|DELETE /api/episodes/{id}/schedule` (`{"at": "next"}` — ближайшее окно, `{"at": "2026-11-28T19:00"}` — своё время по часам Студии).

## Направления

Раздел «Направления»: рубрики и каналы со всеми настройками — режим (новости из источников / тема / своё видео без сценария), длительность и темп, стиль для сценариста, виды вставок и стоки, монтаж (паузы, дубли), публикация, цвета, папка на Google Диске.

- Раньше настройки жили в Google-таблице (лист `directions`). Теперь — в Студии, таблица `studio_directions`; входят в копию базы.
- Процессы n8n К2–К6 читают их узлом «Направления» (Postgres). Запрос — `directions.N8N_SQL`: поля, порядок и значения те же, что отдавала таблица (да/нет — `'TRUE'`/`'FALSE'`, числа — числами), поэтому код процессов не менялся. Добавил поле — допиши его в конец `FIELDS` и обнови запрос в пяти узлах.
- Каждое изменение пишется в журнал действий: что было и что стало.
- **Подача** (карточка «Сценарий»): «Новости с моим мнением» — после фактов разбор и вывод ведущего, как у Наки; «Только новости» — факты и почему это важно, без оценок. Читает К3 (поле `delivery`, в конце `FIELDS`), меняет правила в промпте сценария; подача записывается в выпуск (`meta.delivery`) — потом сравним статистику по месяцам.
- **Папка для видео** — главное у направления: кинул запись в папку направления на Google Диске — К5 через пару минут её заберёт (направление определяется папкой). На карточке направления Студия спрашивает сервер монтажа (`POST /drive/check`, ключ Google только на чтение), видит ли он папку: «Монтаж видит папку … Ждут монтажа: N видео» (видео, которых ещё нет в `k_files`; файлы меньше 1 МБ К5 не берёт), предупреждает про подпапки (видео из них монтаж не берёт) и, если доступа нет, показывает адрес сервисного аккаунта, с которым надо поделиться папкой («Читатель»). Проще всего создавать папки новых направлений внутри уже подключённой — доступ переходит сам. API: `GET /api/directions/{id}/folder` (ответ кэшируется на минуту, `?fresh=1` — спросить заново).
- **Что конвейер сделает с записью** — на карточке списком (паузы и дубли, субтитры и главы, вставки, шортсы, проверка кадров и тексты), там же — куда выйдет (YouTube с доступом, Facebook, Threads, Telegram, окна публикации).
- **Новое направление — из шаблона:** «Познавательное» (история, наука, объяснения: схемы, карты, архивные фото, сток), «Автоматизация и уроки», «Новости из источников», «Своё видео», «С нуля» или «Как …» — копия существующего. Шаблон заполняет режим, вставки, стиль и цвета; остаётся название и папка (поле папки — сразу под названием). Код направления сам получается из названия латиницей («Познавательное» → `poznavatelnoe`).

## Журнал: «Разобрано»

Ошибка, с которой разобрались, больше не горит красным в меню и на «Обзоре»: в «Журнале» у ошибки кнопка «Разобрано», сверху — «Всё разобрано» (все ошибки за неделю). В журнале она остаётся, тише, с пометкой «разобрано»; MCP (`studio_overview`, ошибки за сутки) видит все ошибки с признаком `ack`. Хранится список номеров запусков в настройке `errors_ack` (`POST /api/runs/ack`, `{ids: […]}` или `{all: true}`).

## Подключения

Раздел «Подключения»: YouTube, Facebook, Threads, Telegram — куда публикует конвейер. YouTube входит через n8n (Credentials): Студия берёт из n8n API только имя и тип входа, секретов не видит. Новый вход в n8n появляется здесь сам.

- Видно: подключён ли аккаунт, какие процессы им пользуются, какие направления сюда публикуют, последние публикации.
- Для YouTube в Студии хранятся только подпись, ссылка на канал и заметка (`studio_accounts`, входит в копию базы).
- Вход YouTube проверяется по-настоящему: запись входа в n8n может быть пустой (в Google не входили). Студия спрашивает процесс n8n «Студия · 🔑 Проверка входа YouTube» (`POST /webhook/studio-yt-check`, ключ сервера монтажа; только чтение «мои каналы»; успешные запуски не сохраняются) — раз в 10 минут или по кнопке «Проверить вход». «Подключено» — только когда вход есть, и видно, к какому каналу он привязан.
- Код: `studio/app/connections.py`, страница — `pageConnections` в `studio/web/app.js`.

### Facebook и Threads

Подключаются кнопкой прямо в Студии (вход Meta, OAuth) и публикует их сама Студия — `studio/app/meta.py`.

- Один раз: приложение на developers.facebook.com со сценариями «Управлять всем на своей Странице» и «Доступ к Threads API». Номер и секрет приложения человек вписывает в Студии (секрет — в зашифрованное хранилище, назад не показывается). У Threads свои номер и секрет.
- Адреса возврата: `<STUDIO_PUBLIC_URL>/oauth/facebook/callback` и `/oauth/threads/callback`. Студия строит их из `STUDIO_PUBLIC_URL`, а не из заголовка запроса.
- `POST /oauth/{facebook|threads}/uninstall` и `/delete` — сюда Meta сама шлёт `signed_request` (подписан секретом приложения), когда приложение убрали или просят удалить данные: если это наш аккаунт, Студия забывает ключи и пишет владельцу; для `delete` отвечает ссылкой на политику и кодом подтверждения.
- `<STUDIO_PUBLIC_URL>/privacy` — открытая страница «политика конфиденциальности и удаление данных» (`studio/web/privacy.html`): её адрес Meta просит, чтобы перевести приложение в режим «Опубликовано» (Live). Пока приложение в режиме разработки, его публикации видят только участники приложения.
- Ключи доступа хранятся зашифрованными в настройках `key:meta_fb` / `key:meta_threads` — не попадают ни в API, ни в MCP, ни в копию базы. Ключ страницы Facebook не истекает; ключ Threads живёт ~60 дней и продлевается сам (за 20 дней до конца).
- Публикация: К6 после YouTube зовёт `POST /internal/meta/publish` (ключ сервера монтажа) — Студия ставит выпуск в очередь (`meta.social_pending`) и публикует в фоне: Facebook — длинное видео с диска частями (`upload_phase` start → transfer → finish, до ~45 минут), запасной способ — Resumable Upload API; Threads — текст до 500 знаков (заголовок, темы глав, ссылка на YouTube, если видео там открыто, иначе на Facebook). Перезапуск Студии посреди загрузки не теряет публикацию — очередь подхватит, не больше 3 попыток.
- Повторно безопасно: опубликованное отмечается в `k_episodes.meta` (`fb_video_id`, `threads_post_id`). В выпуске видны кнопки Facebook / Threads или причина и «Повторить Facebook и Threads»; готовый выпуск, которого там ещё нет, можно отправить кнопкой «В Facebook и Threads» (например, если площадку подключили позже).
- Куда публикует направление — «Направления» → Публикация (`publish_facebook`, `publish_threads`; эти поля n8n не читает).

### Telegram-канал

Публикует сама Студия ботом — `studio/app/telegram.py`.

- Один раз: бот (можно бот конвейера, можно новый у @BotFather) — администратор канала с правом «Публикация сообщений». В Студии: «Подключения» → Telegram → «Подключить» → токен бота и адрес канала (`@имя`, `t.me/имя` или номер закрытого канала `-100…`). Студия проверяет (`getMe` → `getChat` → `getChatMember`), что бот видит канал и может публиковать, — в канал при этом ничего не отправляет. «Проверить» — то же позже; «Изменить» — можно поменять только канал, не вписывая токен заново.
- Токен хранится зашифрованным в настройке `key:telegram` — не попадает ни в API, ни в MCP, ни в копию базы. В адресе запросов к Telegram есть токен, поэтому ошибки сети пишутся без адреса, а всё похожее на токен вырезается из текстов ошибок.
- Пост — обложка выпуска (`out/thumb.jpg`) с подписью (до 1024 знаков, разметка HTML): заголовок YouTube жирным, текст для Telegram, ссылка, хэштеги канала и выпуска. Шортс — видео (`sendVideo`, бот отправляет файлы до 50 МБ; больше — Студия так и пишет: выложить самому через «Скачать»).
- «Telegram вместе с YouTube» в направлении (`publish_telegram`, поле было и в старой таблице; К6 его не читает): включено — после К6 пост уходит из той же очереди, что Facebook и Threads (`meta.py`, после Facebook — чтобы была ссылка на видео там). По умолчанию выключено.
- Повтор безопасен: вышедшее записано в `k_episodes.meta` (`tg_post`, `tg_shorts`) и второй раз не идёт; итог — в `meta.social.telegram` (сливается с другими площадками, не затирает их). Последние посты видны в карточке «Telegram» в «Подключениях».
- Для проверки на своём компьютере адрес Telegram подменяется переменной `TELEGRAM_API`.

## Сторож сервера

Обзор → карточка «Сервер»: память, процессор, диск, пики за неделю и прогноз, на сколько дней хватит диска, плюс вердикт «запас есть / следим / тесно».

- Раз в минуту Студия записывает замер в `studio_metrics` (хранится 45 дней, в копию базы не входит). Числа берутся из `/proc` — это весь сервер, а не один контейнер.
- Тревога в Telegram (не чаще раза в 12 часов): на диске меньше 10 ГБ (или 10%), или свободной памяти меньше 6% пять минут подряд.
- Код: `studio/app/hostwatch.py`.

## Копия базы

Каждую ночь в 03:40 (София) бот конвейера присылает в Telegram файл `bez-skazok-db_ГГГГ-ММ-ДД.json` — тихо, без звука.
По субботам в 18:00 рядом приходит копия всех воркфлоу n8n от «Секретаря». Оба файла делает воркфлоу «💾 Бэкап: база — каждую ночь, воркфлоу — по субботам».

- **Что внутри:** источники и их группы, настройки Студии, выпуски со сценариями и вставками, расходы, журнал действий, какие записи с Диска уже обработаны.
- **Чего нет:** ключей сервисов, паролей Студии и собранных материалов источников (их Студия соберёт заново). Поэтому файл можно спокойно хранить где угодно.
- **Восстановить** (сервер с установленной Студией, файл скопирован в `/opt/n8n`):

  ```bash
  cd /opt/n8n && docker compose exec -T studio python -m app.backup restore < bez-skazok-db_2026-11-28.json
  ```

  Восстановление ничего не затирает: что уже есть в базе, остаётся, добавляется недостающее. Потом заново ввести ключ Apify в Настройках.
- **Сделать копию вручную:** `docker compose exec -T studio python -m app.backup export > копия.json`.
- Состав копии задан в `studio/app/backup.py` (`TABLES`). Изменил состав — обнови запрос в n8n: его текст печатает `python -m app.backup sql`.
